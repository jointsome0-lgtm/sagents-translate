# Формат книги, schemaVersion 1

```text
book/
  .gitignore                       # *: содержимое книги не коммитится
  book.json                        # языки, карта глав, backend, настройки
  sources/0001.txt                  # локальная копия оригинала
  context/glossary.json             # только принятые написания
  context/notes.json                # стиль, сюжет, знания, вопросы, замечания
  prompts/manifest.json             # schemaVersion + версия набора
  prompts/rules.md
  prompts/draft.md
  prompts/review.md
  prompts/edit.md
  prompts/verify.md
  chapters/0001/
    accepted.json                   # указатель + история принятия
    versions/v0001/
      run.json                     # авторитетный checkpoint со снимком входов
      translation.md               # текст после редактуры, по завершении сверки
      remaining-issues.json         # оставшиеся замечания итоговой сверки
      proposals.json               # непринятые предложения всех этапов
  .write-lock.sqlite               # служебная блокировка, не данные книги
```

Номера глав задаются ведущими цифрами импортируемых файлов. Нумерация не обязана быть непрерывной, но дубликаты запрещены. `book.json.chapters` связывает номер с файлом `sources/<number>.txt` или `.md`. Можно добавить новую главу, сохранив её в `sources/` и явно расширив карту. Автоматического обхода книги нет.

## Глоссарий

Пример принятой записи в `context/glossary.json`:

```json
{
  "schemaVersion": 1,
  "version": "1",
  "entries": [
    {
      "id": "person-xiaolin",
      "source": "小林",
      "target": "Сяолинь",
      "aliases": [],
      "notes": "Принятое написание для этой книги.",
      "fromChapter": 1,
      "toChapter": null
    }
  ]
}
```

Выбираются только записи, допустимые для текущего номера главы и имеющие совпадение `source` или `aliases` с оригиналом. Совпадение — подстрока без учёта регистра, без морфологии. Алиасы не должны раскрывать будущую личность под видом раннего имени. При разных допустимых написаниях укажите период действия или поясните выбор; автоматического разрешения противоречий нет.

## Заметки

```json
{
  "schemaVersion": 1,
  "version": "1",
  "entries": [
    {
      "id": "prose-style",
      "kind": "style",
      "text": "Диалоги оформлять по русским правилам. Сохранять сдержанный голос рассказчика.",
      "character": null,
      "match": [],
      "fromChapter": 1,
      "toChapter": null
    },
    {
      "id": "letter-belief",
      "kind": "character_belief",
      "text": "Считает письмо потерянным; это её предположение, а не установленный факт.",
      "character": "小林",
      "match": ["小林", "信"],
      "fromChapter": 2,
      "toChapter": null
    }
  ]
}
```

Все поля обязательны. Виды `kind`: `style`, `address`, `plot_fact`, `character_knowledge`, `character_belief`, `interpretation`, `question`, `source_issue`, `user_note`. `character` указывает носителя знания/убеждения; для общей записи — `null`. `match: []` делает заметку общей, иначе нужно хотя бы одно совпадение в исходнике. `fromChapter` — первая глава, где сведения можно использовать, `toChapter` — последняя включительно либо `null`. Вторая запись примера не попадёт в главу 1.

Глоссарий и заметки сохраняются в снимке запроса отдельными списками с исходными метками. Предложения модели не подмешиваются автоматически. Поздние главы и их переводы не используются для подготовки раннего контекста. Пользователь отвечает за содержание и временную разметку принятых записей; MVP не распознаёт спойлеры внутри текста заметки.

## Checkpoint и принятие

`run.json` — JSON-конверт `{schemaVersion, checksum, run}`. `checksum` — SHA-256 канонического объекта `run`. В `run.inputs` находятся:

- `workflow: "chapter/1"`, номер главы, вид работы;
- точный текст исходника и SHA-256 его UTF-8 содержимого, языки;
- выбранный контекст с версиями файлов и хешем;
- все применённые промпты, версия набора и хеш содержания;
- модель и поддерживаемые настройки, идентичность backend;
- ограничения повторов/разбиения;
- для редакции — замечания с хешем, версия основы и хеш/сегменты её текста.

`fingerprint` — SHA-256 всех `inputs`. Сначала сохраняется подготовленный снимок; далее перед каждым обращением — попытка `pending`, после завершения — её исход и checkpoint этапа. Абзацы получают стабильные id `p1`, `p2`, …; при делении предложения — `p1.1`, `p1.2`. Перевод обязан вернуть все id по порядку; сверка обязана перечислить все проверенные id. Результаты этапов содержат собственный хеш и дату. Невалидный ответ оставляет только факт попытки, её код и известный usage.

У частей есть дерево разбиения. Этапы родителя остаются в истории, но конечный текст составляется из актуальных листьев в порядке исходника. Предложения собираются со всех четырёх этапов этих листьев; замечания финальной сверки — только с `verify`. Восстановление после обрыва отмечает незавершённые попытки как `interrupted`. Если ответ дошёл до провайдера, но не попал на диск, повторная попытка может означать повторный расход.

После каждого завершённого этапа весь `run.json` атомарно заменяется. Завершённая версия больше не меняет этот файл. Три итоговых файла — производные представления checkpoint: если завершение прервалось между их записями, повтор команды восстановит их без модели. Не редактируйте их для изменения принятого текста: используйте `revise` с замечаниями. Не правьте checksum вручную.

`accepted.json` содержит версию, хеш её текста, дату и историю предыдущих принятий. `accept` разрешён только для завершённой версии с текущим исходником, языками, контекстом и промптами. Принятие другой модели не требует, чтобы она совпадала с текущим default в `book.json`. Наличие оставшихся замечаний не запрещает осознанное принятие. Старые принятые тексты хранятся в своих неизменяемых версиях.

`status.stale` сравнивает материалы (оригинал, выбранный контекст, языки, промпты) с текущими файлами. Он не запускает backend и не проверяет текущие credentials, окружение провайдера или доступность модели. Полное совпадение модели/настроек проверяется fingerprint при `chapter`/`revise`. Пустые каталоги версий, оставшиеся до первой записи checkpoint, пропускаются, их номера не используются повторно.

Один процесс держит SQLite-транзакцию через весь изменяющий запуск. Конфликт завершается сразу; блокировку нельзя обходить удалением файла. Ручные правки материалов во время перевода обнаруживаются перед следующей попыткой и перед завершением; выполнение останавливается как `inputs_changed`. Снимок старого результата сохраняется, следующий запуск создаст версию с новыми входами. Используйте обычный локальный диск и храните резервные копии каталога книги.
